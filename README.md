# FantasyPerf

本项目使用 [MIT 许可证](LICENSE)，允许使用、修改和分发；分发时需保留版权和许可声明。

面向桌面浏览器的洞洞板布局工具。以真实孔位、引脚标注、锡线和跳线为核心，不依赖元件封装库，不做电气连接校验。

## 启动

需要 Node.js 20 或更新版本。应用运行不依赖第三方包：

```sh
npm start
```

打开 http://localhost:5173。`PORT=8080 npm start` 可指定端口（Windows PowerShell 使用 `$env:PORT=8080; npm start`）。

```sh
npm run build
```

会生成可由任意静态 HTTP 服务托管的 `dist/`。前端没有后台、登录、遥测或外部资源请求。请使用 HTTP 服务打开，避免 `file://` 对 ES 模块的限制。

## 设计与使用

- 顶部外观选择器支持浅色、深色和跟随系统（默认），可实时响应系统变化，选择保存在当前浏览器。画布与界面一起切换；原理图图片保留原色，导出 PNG 使用浅色，外观偏好不写入项目。
- 板尺寸为 2–100 列 / 行，固定 2.54 mm 孔距，默认 30 × 20 孔。
- **正面 = 元件面；背面 = 焊盘面。** 元件、跳线在正面，锡线、贴片元件在背面；翻面采用左右镜像，孔位标识绑定实际孔位，A1 角标帮助对照。
- 左侧「元件」（快捷键 C）统一提供预设、自定义和文件导入。预设按单排、双排（排距 1 孔 / 3 孔）、两焊盘贴片分类，带引脚排列预览；支持搜索 NE555、8 脚单运放 / 双运放、14 脚四运放等通用 DIP 布局。库内明确区分「通用引脚排布」与「常用元件」：通用排布和新建自定义元件默认不带引脚标注；NE555、8 脚单运放（TL071）、8 脚双运放（LM358）、14 脚四运放（LM324）按指定型号预置功能标注，放置后的实例可独立修改。
- 功能标注依据 TI 的 DIP / PDIP 顶视引脚定义：[NE555](https://www.ti.com/lit/ds/symlink/ne555.pdf)、[TL071](https://www.ti.com/lit/ds/symlink/tl071.pdf)、[LM358](https://www.ti.com/lit/ds/symlink/lm358.pdf)、[LM324](https://www.ti.com/lit/ds/symlink/lm324.pdf)。单运放使用当前 TL071 P 封装定义（1、5、8 脚为 NC）；特殊引脚按实际型号修改。双排顺序为左侧从上向下、右侧从下向上。
- 单排、双排或自定义引脚组；可粘贴多行标注；名称和引脚标注可独立拖动并按半格（半个孔距）吸附，指示连线仅在选中元件时显示，默认位置也会显示。支持拖动元件、旋转、复制、双击编辑。选中元件后「导出元件文件」，通过「元件 → 导入元件」复用；包含名称、孔位、标注及贴片类型，不带原板上的位置和旋转。
- 左侧「贴片」可放置贴片电阻或电容（0603 / 0805 仅作说明，无封装选择）。点击焊盘面两个相邻孔位之间落位；R 旋转，拖动按孔距移动，可在名称中填写阻值或容值。元件面淡显，实例复制保留原名，项目文件和 PNG 均保留贴片元件。
- 锡线始终横竖，可在焊盘面或元件面直接绘制、选中和修改。元件面显示同一条焊盘面线路的镜像投影，便于对照元件；不会创建另一套线路，导出仍按物理板面显示。选择锡线工具保留当前视角。点击起点和路径点，Enter 或双击完成，Tab 切换直角方向，Esc 取消。
- 跳线在元件面，支持两孔直连与直角折线。选中线路后拖动端点或折点编辑；直角线同步调整相邻折点，保持横竖。
- 裁线长度 = 贴板中心线路径 × 2.54 mm + 起点余量 + 终点余量，默认两端各 3 mm，计算保留完整精度，显示一位小数。
- 跳线交叉处画小跨线弧，仅用于视觉区分，不增加计算长度。
- 线路绑定孔位，单独移动元件不会移动线路。Shift 点击多选、拖动空白区域框选；在并排视图中可以选择两面的对象并整体移动。
- 左侧「参考图」可导入一张原理图图片，拖动图片任意移动，右侧调整大小、透明度、显示 / 隐藏、替换或移除。图片标题栏和属性面板可临时隐藏参考图，用画布上的「显示参考图」恢复；临时隐藏不改变项目文件或撤销记录，刷新页面后恢复。参考图保持正向，独立于板面翻转、平移和缩放；位置和图片随项目保存，支持撤销重做。图片仅作为工作台参考，不加入布线 PNG 和 CSV。
- 自动保存当前项目到浏览器 localStorage；打开 / 新建可撤销。存储不可用时提示手动导出，不会误报已保存；检测到另一窗口写入则暂停当前窗口自动保存，避免互相覆盖。
- 导出可编辑 JSON、元件面（正面）/ 焊盘面（背面）/ 并排 PNG，以及带 UTF-8 BOM 的全部元件 CSV 清单。清单逐行列出元件、贴片元件与跳线：类别、所在板面、基准孔或起终点、引脚孔位与标注、路径长度、两端余量与裁线长度。锡线在现场焊接，不列入元件清单。
- 板尺寸缩小时若有对象超出范围，则拒绝修改，避免丢失设计。允许元件自由重叠，不做占孔检查。

首次打开为空白板，可用左下角的示例按钮打开设计者提供并验证的「基于555定时器的LED多谐振荡器」：10 × 8 孔，含 9 个元件、2 根跳线、完整锡线布线及内嵌原理图参考。手机查看器使用同一示例。

## 数据与边界

项目文件写入三段式版本：`format: "FantasyPerf"`、`version: "1.2.0"`，以及 `meta`（`app` 生成工具、`appVersion` 工具版本、`savedAt` 导出时间）。三段的职责固定：

| 位 | 用途 | 兼容性 |
| --- | --- | --- |
| 大版本 | 数据含义不兼容的重构 | 与工具的大版本不同则拒绝打开；正常情况下长期保持 1 |
| 中版本 | 新功能带来的向后兼容扩展 | 旧文件自动升级；高于工具支持的中版本提示升级工具 |
| 小版本 | 仅修复，不改变数据含义 | 同中版本内双向通用，读入时归一到当前版本 |

导出始终写入当前的 `version` 与 `meta`；打开时先按 `version` 升级到当前格式，再逐字段验证，因此旧文件（含早期使用过的整数版本号 1 / 2）无需手动转换。升级步骤登记在 `src/core.js` 的 `FORMAT_MIGRATIONS`，每一步只补全或翻译字段，不改变已有数据的含义；递增中版本时必须补一条步骤（小版本若不改变数据，可沿用同大版本内最近的步骤）。限制 5 MB 文件、3000 对象、单元件 256 引脚、单线路 2000 路径点。内部使用元件面的整数孔位坐标；镜像只在视图层发生，长度计算与导出数据保持相同坐标体系。

元件文件使用独立格式 `FantasyPerfComponents`，当前版本为 `1.2.0`，与项目版本分别维护，但遵循相同的大 / 中 / 小版本兼容规则。旧整数版本 `1` 按 `1.0.0` 处理，导入时先按 `COMPONENT_MIGRATIONS` 逐级升级，再校验元件；同中版本的补丁版本可互相读取，更高中版本提示升级工具，不同大版本拒绝导入。`1.0.x → 1.1.0` 将旧 `appVersion`、`exportedAt` 移入 `meta.appVersion`、`meta.savedAt`，保留原始导出信息及全部元件内容；缺失的历史信息记为 `null`。重新导出写入当前格式、工具版本和新的导出时间，原文件不会被改写。今后增加元件格式中版本时须登记对应迁移步骤。`1.1.x → 1.2.0` 新增可选名称偏移 `nameDx` / `nameDy`，旧文件缺省时保持原名称位置；项目格式采用相同扩展。元件文件上限 10 MB，每份 1–100 个元件。

参考图支持 PNG、JPEG、WebP、GIF（首帧）和 BMP，导入文件上限 20 MB。为兼顾清晰度和浏览器存储容量，图片会按最长边 2400 像素压缩，压缩后的内嵌数据上限约 1.8 MB。旧版本不含参考图的项目仍可导入。

自动保存是当前浏览器、当前网站地址下的恢复机制，清除网站数据会丢失自动存档与旧版模板；仅清理图片 / 文件缓存通常不会清除 localStorage。请导出项目文件作为正式备份。元件复用使用独立的 `.fantasyperf-components.json` 文件，由用户管理；导入列表只在本次页面会话保留，刷新后可再次导入，已放到板上的元件随项目保存。旧版模板仍可在「元件」窗口中放置、单独导出或全部导出，也可逐项删除；导出不会自动删除模板，手动删除会写回浏览器存储，刷新后不再出现，不影响已导出的文件或板上元件。不再向浏览器新增模板。项目文件包含全部实例，但不包含旧版模板库。

桌面宽度至少 1000 px 时提供完整编辑；手机、触摸平板或窄窗口自动使用只读查看模式。不提供原理图编辑、网表、自动布线、仿真或电气校验。尺寸读数是首末孔中心距，不是实体板外形尺寸。

## 开发与测试

开发主仓库为 [GitHub](https://github.com/Fantastair/FantasyPerf)。PR 与 `main` push 由 GitHub Actions 执行单元测试、部署安全检查、构建及 Chromium / Firefox / WebKit 两分片矩阵测试；内网服务器每天北京时间凌晨 3 点或手动触发时拉取最新且 CI 已通过的 `main` 发布。配置与运维见 [部署说明](docs/deployment.md)。

```sh
npm install
npm test
npx playwright install chromium firefox webkit
npm run test:e2e
npm run build
```

- `src/core.js`：纯数据模型、几何、长度、历史记录、格式版本升级与项目校验。
- `src/library.js`：按引脚排布分类的通用元件预设。
- `src/component-files.js`：独立元件文件格式、版本升级、导入校验和旧模板迁移校验。
- `src/renderer.js`：Canvas 绘图、镜像变换、标注与跨线弧。
- `src/theme.js`：首屏外观初始化、系统外观监听与偏好持久化。
- `src/reference.js`：参考图导入、拖动、属性与图片压缩。
- `src/app.js`：编辑器状态、交互、属性面板、自动保存、文件导入导出。
- `test/core.test.mjs`：几何、长度、历史、CSV 清单、版本升级与损坏文件的单元测试。
- `test/component-files.test.mjs`：元件文件往返、损坏输入和通用布局的单元测试。
- `test/browser/editor.spec.js`：通过浏览器实际操作完成验收流程，包含导出、重开和导入。

`npm test` 不需要安装依赖。Playwright 只用于开发测试，不会进入发布产物。

## 本地手机查看测试

电脑编辑：`npm start`，打开 http://localhost:5173。电脑也可打开 http://localhost:5173/?view=1 强制预览只读模式。

同一 Wi-Fi 下使用手机：

```sh
npm run preview:lan
```

此命令构建并仅提供 `dist/`，监听本机 5174 端口。手机打开 `http://电脑的局域网IP:5174`（例如电脑网络设置中显示的 IPv4 地址）。不需要账号、数据库或外部部署；电脑需要保持服务运行，系统防火墙需允许本地网络访问。使用 Ctrl+C 停止。

手机可打开导出的项目文件，切换元件面/焊盘面、上下核对两面、单指平移、双指缩放、点击元件查看引脚，或查看跳线裁线清单与原理图参考。查看器不提供编辑入口，也不会写入或覆盖浏览器的编辑存档；打开的文件只用于当前查看会话，刷新后需重新打开。原理图参考可在弹窗内查看，不允许修改位置。

公共库目前是通用引脚布局，并不包含未经实物核对的具体芯片/模块型号。可在 `src/library.js` 中维护公共定义。`src/viewer.js` 管理只读触摸手势，触摸控制器不接收项目对象，避免误修改布局。
